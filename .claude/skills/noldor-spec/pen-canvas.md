# /noldor-spec — working on a design canvas

Read by a spec session whose UI or architecture verdict is `required`: [`ui-design.md`](ui-design.md) and [`arch-design.md`](arch-design.md) send the session here before their first pencil call, and step 7.5 sends it here again to take the verdict.

The text below is written for the UI canvas. On the architecture canvas every rule applies verbatim with `docs/design/architecture/` for `docs/design/ui/` and `archWaiver` for `uiWaiver`; `arch-design.md` names its own verdict command.

## Before every write

- **Assert the write target before every pencil write — a wrong `filePath` is a silent write, not an error.** `execute` routes by `filePath` only while that file exists; a path that does not (a typo, a worktree-relative path, a file nothing ever created) falls back to whatever canvas the editor currently has open, and the write lands there with no diagnostic. Call `get_app_state` first and confirm the open document is the `.pen` you are about to write; when it is not, open the intended file (`pnpm noldor design pen-bridge --pen <path>`) and re-check rather than trusting the argument. Skipping this once cost a baseline four pages (Q-0187): the session held a worktree path, the editor held a baseline `.pen` under `docs/design/ui/baseline/`, and the edit landed on that baseline. The `checks shared-files` `.pen` guard rejects that class at commit time, but only after the write — the assertion is what prevents it.
- **Wake the bridge before you conclude the editor is unavailable.** Pencil MCP is the `.pen` write API, and every MCP call fails with `A file needs to be open in the editor` until *some* `.pen` is open in VS Code (via the pen.dev extension `highagency.pencildev`). That is a liveness gate, not a per-file lock: once any file is open, `execute` reaches any `.pen` by `filePath`. Run `pnpm noldor design pen-bridge` — it finds a tracked `.pen` and asks the editor to open it (exit 1 = the repo tracks none, so author one in VS Code and save it into the repo; exit 3 = the pen.dev extension is not installed, so VS Code would show the file's raw JSON instead of a canvas) — then retry the call. Exit 0 means the open was requested, not that it happened. The same error also means the MCP server is pinned to another editor, which `pnpm noldor checks pen-bridge` tells apart — it expects `--app visual_studio_code`. If instead the pencil MCP **tools are absent altogether**, the harness is the cause: the server does not connect under the Claude Code VS Code extension, and only a terminal Claude Code session fixes that. `checks pen-bridge` leads with that row.
- **Editor unavailable:** only after the wake attempt above, stop for an explicit operator waiver — record it in the session marker (`uiWaiver: { reason, at }`) and in spec prose; never write the FD `design:` field. A session waived **before Seed** produces no `.pen` and no `links.design`; a waiver taken any time **after Seed** — the bridge died mid-iteration, or at the verdict — is covered by the verdict bullet below, which keeps the seeded `.pen` rather than orphaning it. A closed editor and an absent editor look identical from Node, so waiving without the wake attempt buys permanent baseline debt for a fixable problem.

## After a write

- **Verify a freshly created node in a FOLLOW-UP `execute` call, never in the same one.** The pen skill states that screenshots “reflect the changes made earlier in the same `execute` call”; for new `text` and `path` nodes they do not — those come back blank in a `TakeScreenshot` issued from the call that created them, while frames carrying a `fill` and nodes made with `Copy` render immediately. Nothing is wrong with the schema when this happens: screenshot again in the next call and the node is there. An agent that believes the same-call screenshot instead diagnoses its own correct `.pen` as broken and rewrites it — which is the second reason this step builds from `Copy` of an existing node wherever a page already has one.

## Take the operator's verdict

**The design is not settled until it is given.** Runs when `uiVerdict` is `required`. A session carrying `uiWaiver` has no design to ratify, so it **skips the ratification steps (a)–(g) below** — but not the **Waiver after Seed** paragraph that follows them, which still applies whenever the waiver postdates Seed, and is the only place that keeps the seeded `.pen` and its `links.design` from being orphaned. Nothing outside this conversation distinguishes a design an operator ratified from one nobody saw, so the verdict is taken here and written down here. It is taken **last** — at step 7.5, after self-review — because the record binds the spec as well as the design, so the spec it binds must be the finished one; the steps live in this file, beside the hazards every canvas write shares. In order:

  (a) **Open this session's `.pen` by path first.** Resolve the path by **dialogue key, never by re-deriving today's date** — the file is `docs/design/ui/*-<dialogue-key>.pen`, and its date prefix is the day Seed ran, which a session resumed after midnight no longer matches. Then `pnpm noldor design pen-bridge --pen <that resolved path>`. Order matters: `get_app_state` reports whatever canvas the app currently has open, so checking pages before opening reads some other document — the read-side twin of the Q-0187 write hazard. A **bare** `pen-bridge` is also wrong here: its candidates come from `git ls-files -- '*.pen'` (the index), and this `.pen` is untracked until gate Step 2.5, so the ranking would hand the editor a different tracked design.

  (b) **Then verify against that file.** Via `get_app_state`, confirm the open document is this session's `.pen`. `pen-bridge` and `code` can return before the editor has switched canvases, so a mismatch here is expected rather than exceptional: re-issue the open, wait, and re-check **once**; if it still reports another document, stop and take the waiver path below rather than continuing — approving against whatever canvas happened to be open is the exact hazard this bullet exists to prevent, and it is the one failure that must never degrade to a silent pass. Only once the right document is confirmed open, read its page list — `Print(Get(document, {depth: 1}).children.map(c => c.name))` through `execute` — and run `pnpm noldor design verdict --pen <this session's .pen> --coverage --spec <this spec> --editor-page "<name>"` with one `--editor-page` per top-level page, exactly as listed. Exit 0 means the `FINAL:` pages are exactly the rows of the spec's `### Design coverage` table and every criterion has a row; exit 1 lists each missing, doubled or undeclared page and each criterion the table leaves out. It judges the names it is given, not the file, so it works before the editor saves. Then confirm that no `FINAL:` page names a surface outside the verdict's `affectedSurfaces`: `unmappedPaths` cannot catch that, because it is derived from changed *paths* and never sees what is inside the `.pen`. Any gap means the iteration is unfinished: return to **Iterate** — draw the missing page, delete the stale one, or correct the table where a criterion was misread — and come back, which costs no revise round.

  (c) **Show the pages.** Navigate to each winner and each alternative in turn, naming them as they are shown. Listing page names in chat satisfies nothing — it recreates the unwitnessed selection this bullet exists to end.

  (d) **Ask for one atomic verdict** over the whole `FINAL:` set — approve / revise. A multi-surface feature is approved as one design or not at all.

  (e) **On `revise`:** the operator says what to change, and the step returns to **Iterate**; a bare "revise" with no direction is re-asked rather than acted on and consumes no round. A revise verdict writes **no** approval sentence — it is not an approval and must never read as one.

  (f) **On `approve` only, write it:** add to the spec's `## Design`, per affected surface, that the operator approved the named final variant over the named alternatives. **Record** ran earlier and cannot assert an approval that had not happened; it names the choice, this names the ratification. Then, after that sentence is on disk, write the machine half. Read the editor's page list first — `Print(Get(document, {depth: 1}).children.map(c => c.name))` through `execute` on this session's `.pen` — then run `pnpm noldor design verdict --pen <this session's .pen> --approve --surface <s> --spec <this spec> --editor-page "<name>"` (one `--surface` per affected surface; one `--editor-page` per top-level page, exactly as the editor listed it; approve-with-reservations adds `--reservation "<text>"`). The CLI reads the pages of the file on disk and refuses with exit 1 when they differ from the editor's: the editor has not saved. Ask the operator to save the `.pen` in VS Code, then re-run — never drop an `--editor-page` to make the lists agree. It also re-runs step (b)'s coverage check on the file and refuses with exit 2 on any gap, writing nothing: the table or the pages moved after (b), so return to **Iterate**. On exit 0 it prints every page it signed; check that count against the pages the operator was shown. It writes `.noldor/design-approval/<pen-stem>.json`, bound to the `.pen` blob and to this spec's blob — the record the pre-commit guard and the `ui-reviewer` lane read. Any other non-zero exit is a failed verdict step: surface it and do not proceed as approved until a re-run exits 0 (re-running overwrites, so it is idempotent). The record commits with the spec and the `.pen` at gate Step 2.5 — without it staged, `checks shared-files` refuses the `.pen` (`pen-unapproved`).

  (g) After two revise rounds, additionally offer **approve with reservations**, recording the reservation beside the approval — the bound governs what the agent must offer, not what the operator may do, so revising again stays legal. There is no rejection verdict: a design that is not approved is being revised.

  **Waiver after Seed (bridge died mid-iteration, or here at the verdict).** One rule covers both, and **which side of Seed a waiver fell on is read from the filesystem, not from the marker**: `uiWaiver` carries only `reason` and `at`, so after an interruption the recovery signal is whether any `docs/design/ui/*-<dialogue-key>.pen` exists — match on the **dialogue key, never the date**, exactly as `ui-design-resolve.ts` does (`penSlugFromFilename(entry) === key`). A session resumed after midnight re-derives today's date, so a date-stamped probe would miss the file Seed wrote yesterday and orphan it — the precise failure this paragraph exists to prevent. Such a file exists only if Seed ran, which is exactly the condition that decides retention. No extra marker state is needed. Record `uiWaiver: { reason, at }` in the session marker exactly as the Editor-unavailable bullet does — downstream `ui-design-resolve.ts` keys on `session.uiWaiver` to return `not-applicable`, so a waiver that lives only in prose leaves the review lane expecting a ratified design — then run `pnpm noldor design verdict --pen <the seeded .pen> --waive --reason "<why the verdict could not be taken>"` so the committed-but-unratified design carries its reason to `main` in machine-readable form (the pre-commit guard refuses a feature `.pen` with no record — the `waived` member is what admits this flow), then **keep the seeded `.pen`** and commit it with the spec, and **ensure `links.design` names it**: keep the pointer Record wrote, or set it here when the bridge died before Record ran. Never unset it. Archival itself does not depend on the pointer — `archive-resolve.ts` finds the `.pen` by its filename dialogue key under the `branchAdded` ownership gate, and never reads `links.design` — but `rewriteArtifactLinks` (`archive-cli.ts`) only repoints a pointer that *already* names the moved path, so clearing it makes that pass a no-op and the FD ends the session with no link to the archived design. The link names a committed-but-unapproved design, and the waiver note in the spec must say so, so a later reader does not mistake an archived `.pen` for a ratified one. The FD `design:` field is still never written — it is the operator's override, not a verdict record.
