# Graph Integration

Noldor's SDD detectors (Detector 13 onward) consume a knowledge graph
generated by [`graphify`](https://pypi.org/project/graphifyy/). This page
describes the substrate: which graph file to read for what, the
staleness gate, and the path → FD lookup pattern detectors use.

The graph itself lives in `graphify-out/`, built by
`pnpm noldor graphify build` (the graph, its report and both toon files).
The `update-knowledge-graph` workflow runs it after every merged `feat`,
`fix` or `refactor` PR, and the release sweep runs it too. It contains hyperedges,
god nodes, community structure, and cross-package bridges that no file
scanning replicates.

## Which file to use

| File                            | When to use                                                                                                                                         |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `graph.brainstorm-summary.toon` | **Default starting point.** Quick orientation, brainstorming, "what packages exist", architecture questions. Read this first in every conversation. |
| `graph.brainstorm.toon`         | **Deep work.** Refactoring, tracing cross-cutting concerns, community-level design, finding god nodes. Use when summary isn't enough.               |
| `GRAPH_REPORT.md`               | **Audit.** God node analysis, surprising connections, community cohesion scores, knowledge gaps.                                                    |
| `graph.json`                    | **Programmatic queries only.** Don't read raw — use toon files instead. Only for scripts or when you need exact IDs/edge weights.                   |
| `graph.html`                    | **Visual exploration.** Open in browser, click communities. Not for LLM consumption.                                                                |

## Rules — when to read what

- **Before any codebase exploration**, read
  `graph.brainstorm-summary.toon`. This includes subagent prompts —
  always instruct them to read the toon first.
- Escalate to `graph.brainstorm.toon` only when the summary doesn't
  answer your question.
- Never read `graph.json` directly unless doing programmatic work — the
  toon files exist specifically to save tokens.
- Outside the pre-release sweep, regenerate the graph on demand (e.g.
  before deep refactor work, or when brainstorming needs accurate
  structure). Skip per-feature regen — bounded drift between releases is
  acceptable.
- `pnpm noldor graphify build` renders the toon files itself. After a
  `/graphify` run (the sweep's `--full-semantic` opt-in), run `pnpm toon`
  to regenerate them.

## Pre-release sweep

The pre-release sweep — `pnpm noldor graphify build` → `/noldor-refactor`
against the new `GRAPH_REPORT.md` (skipped by
`pnpm noldor graphify refactor-precondition` when god nodes and cohesion are
unchanged since the last tag) → verify README → build again — is encoded in
the [`/noldor-release-sweep`](../../.claude/skills/noldor-release-sweep/SKILL.md) skill and
required before any minor or major `pnpm release`. See
[`versioning.md`](versioning.md) "Pre-release sweep" for the release-flow
contract.

Both graph builds in the sweep are **AST-only by default** (structural
extraction, no semantic subagent fan-out): `/noldor-refactor` keys off god nodes,
cohesion, and dead exports, which all come from the AST graph, and the build
is deterministic and takes seconds. The full-semantic pipeline is an explicit
operator opt-in (`/noldor-release-sweep --full-semantic`) reserved for deep passes.

**The graph is a function of the commit and the lock.** The builder runs
`src/graphify/build-graph.py` in a copy of HEAD's tree under `PYTHONHASHSEED=0`,
with every Python package pinned in `src/graphify/graphify-requirements.txt` and
installed into a venv under `~/.cache/noldor/graphify/` (`$XDG_CACHE_HOME` when
set). Pinning `graphifyy` alone was not enough: the v1.13.0 sweep ran CI's recipe
on the operator Mac and found 222 communities where CI found 215 on the same
nodes and edges, because networkx and the tree-sitter grammars had moved. Under
the lock, the Mac rebuilt CI's committed graph byte for byte. The interpreter
must be the lock's Python minor; point `NOLDOR_GRAPHIFY_PYTHON` at one when
`python3` is another. Right after a graph PR merges the build is a no-op: the
graph's `built_at_commit` shows that only `graphify-out/` changed since. Bumping
the lock reshuffles the graph once, so it lands in a PR of its own.

## graph-fd-lookup substrate

Detectors that need to map a code file to its owning FD use the path → FD
lookup substrate at
[`../../src/garden/graph-fd-lookup.ts`](../../src/garden/graph-fd-lookup.ts).
Three exports cover the pattern:

- **`loadFreshGraphOrWarn(graphPath, srcRoots)`** — load `graph.json`
  with the staleness gate baked in. Returns `{ ok: true, graph }` or
  `{ ok: false, gap }` so the consuming detector can propagate the
  meta-gap as its only finding when the graph is missing or stale.
- **`buildFileToFdsMap(features)`** — invert every FD's `links.code`
  array into a `Map<path, Set<slug>>`. Co-ownership is real (a meta-FD
  can name a file already owned by a primary FD), so the value is a set,
  not a single slug.
- **`getFdOwnersForFile(filePath, map)`** — look up owners for a file,
  walking ancestor directories so a `links.code` entry like
  `packages/sample-scenes` covers
  `packages/sample-scenes/src/empty-room.ts`. Owners from a direct match
  and ancestor-directory matches are unioned.

Used by:

- Detector 13 (co-tag suggestion).
- Detector 9 (orphan owner suggestion) when it ships — see
  [`../backlog.md`](../backlog.md) "SDD Detector 9".
- Detector 10 (untagged-test slug suggestion) when it ships — see
  [`../backlog.md`](../backlog.md) "SDD Detector 10".

## Lift audit — which detectors gain graph signal

Reference table for deciding which of the 12 pre-existing SDD detectors
to fold into the graphify-augmented family beyond the initial 13th
(co-tag, shipped). Detector numbering and names match the
[`garden-and-drift.md`](garden-and-drift.md) detector table; detectors
14–19 postdate this audit and are metadata/audit checks with no graph
consumption.

| #   | Detector                           | Lift       | Augmentation                                                                                           |
| --- | ---------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------ |
| 1   | Done features without tests        | Weak       | Per-FD coverage % from import edges; sharper than "tests array empty".                                 |
| 2   | Done features without docs         | Medium     | Community-based doc co-tag suggestion.                                                                 |
| 3   | Features without spec              | None       | Pure metadata.                                                                                         |
| 4   | Done features missing `introduced` | None       | Pure metadata.                                                                                         |
| 5   | Untriaged ideas                    | **Strong** | Semantic-similarity match idea text vs FD names → propose auto-`merge:<slug>` for `/noldor-triage`.           |
| 6   | Stale backlog entries              | None       | Pure age check.                                                                                        |
| 7   | Spec files not referenced          | Medium     | Spec content vs FD community match.                                                                    |
| 8   | Plan files without matching spec   | None       | Pure filename match.                                                                                   |
| 9   | Code files not referenced          | **Strong** | Suggest probable owner FD via file's community membership (instead of just listing as orphan).         |
| 10  | Tests without `@tests:` tag        | **Strong** | Auto-suggest `@tests:` slug from imports + `links.code`. Same engine as 13th, runs on absent-tag case. |
| 11  | Tutorials without `@feature:` tag  | Medium     | Community-driven `@feature:` slug suggestion.                                                          |
| 12  | README architecture drift          | None       | Pure FS check.                                                                                         |

Strong-lift family: 9, 10, 13 — same "path → FD" substrate (see
[graph-fd-lookup](#graph-fd-lookup-substrate) above), same staleness
gate. Standalone strong-lift: 5 (idea-merge suggestions, touches
`/noldor-triage`). Medium-lift candidates (2, 7, 11) only worth chasing if
false-negatives accumulate.

## Staleness gate — graph older than latest source commit

Detectors that consume `graph.json` check its mtime against the largest
mtime of files under tracked source roots (typically
`['packages', 'apps', 'scripts']`). If any source file is newer than the
graph, the detector skips with a single meta-gap that includes regen
instructions, rather than emitting stale findings.

Files git ignores never count. Scan roots are also where build and test
tools write their output — Playwright's `test-results/` under `apps/web`
is the case that surfaced this — and before the exclusion one e2e run
staled the graph with no source change, so a release that ran its tests
aborted its next attempt on report drift nobody had caused. A tracked
file that matches an ignore pattern, and a new file not yet added, still
count. Outside a git repository nothing is excluded.

Implemented in `loadFreshGraphOrWarn` (see above). Mtime-based staleness
is intentionally cheap; the pre-release sweep already rebuilds the graph,
so any false-stale (e.g. after `git checkout`) is harmless — it forces a
regen, which is the right outcome anyway.

## Dependency on graphify v0.4.20+

Path normalization (cross-package edge accuracy, no double-counted edges)
requires graphify ≥ 0.4.20. The bug was fixed upstream in commit
`a507c97` (`fix #414 JS imports_from path normalisation`); lower versions
emit edges keyed by inconsistent paths and silently break the substrate.
The builder's lock pins graphifyy 0.7.8, a release that includes this fix.
