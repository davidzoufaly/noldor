# /noldor-spec — UI design (step 1.5, `required`)

Read when step 1.5's UI verdict is `required`. **Read now:** [`pen-canvas.md`](pen-canvas.md) — the hazards of every pencil write, and the verdict step 7.5 takes.

- **Zero affected surfaces OR any unmapped paths ⇒ do not proceed:** prompt the operator to extend `uiPaths`/`uiSurfaces` (config edit rides the branch) or accept the implicit `app` surface; the step refuses to conclude while the surface set is empty or the verdict's `unmappedPaths` is non-empty — a partially-mapped verdict would leave those paths outside every baseline.
- **`required` means this session touched a UI surface, not that the pixels moved.** When the work provably leaves every affected surface rendering identically — a refactor behind an unchanged render, a type-only change under a `uiPaths` glob — the answer is to *record* that, not to seed a `.pen` whose `FINAL:` pages are copies of its `BASE:` pages. Such a session skips the **Seed / Iterate / Record** bullets below (and, like any waived session, ratification steps (a)-(g) in `pen-canvas.md`) but performs every other bullet in this file, and still continues to step 1.6. Record it in two places: a line in the spec's Design section naming each affected surface and why it is visually unchanged, and `uiWaiver: { reason, at }` in the session marker (the same shape the Editor-unavailable bullet writes). Two things this is **not**. (1) Do not simply skip Seed and say nothing: the `ui-reviewer` lane recomputes the verdict from the real `origin/main..HEAD` diff at code stage and terminates `cannot-review / no-design-artifact` — red under `blocking` — for a session that changed UI paths and owns no design, and `uiWaiver` is the only thing it reads as `not-applicable / waived` (`src/cr/lanes/ui-design-resolve.ts`). (2) Do not reach for FD `design: skip`: it is the operator's override, it lives on the FD rather than the session, and on an attach path that FD is the *parent* — so it would suppress UI review for every future session on that feature. Baseline freshness is orthogonal and unaffected either way: the surface goes `stale` because a UI-path commit postdates the baseline's receipt commit, seeded `.pen` or not — repay it at gate Step 4 with `pnpm noldor design capture --surface <surface> --vouch-only` when the committed baseline is genuinely still correct.
- **Seed — copy the file on disk, then rename its pages; `execute` has no cross-file copy.** `Copy(path, parent)` takes a node id *inside the document `execute` is routed to*, so baseline pages cannot be copied into a fresh `.pen`, and `Get`-then-`Insert` is no fallback (a captured baseline runs to ~1500 nodes). Nothing but the editor should author a `.pen` — the format is the editor's to version — so the filesystem copy is also what creates the file: `cp docs/design/ui/baseline/<surface>.pen docs/design/ui/<date>-<dialogue-key>.pen`, then open the copy (`pnpm noldor design pen-bridge --pen <path>`) and rename its pages to `BASE:<surface>: <name>` with `Update(<pageId>, {name})`; `Print(Get(document, {depth: 1}).children.map(c => [c.id, c.name]))` enumerates them without dumping the subtree. **Rename before Iterate, always:** a captured baseline's pages already carry the `FINAL:<surface>: <state>` prefix — the consumer's capture command owns it (`PAGE_PREFIX` in its states table) — while verdict step (b) holds every `FINAL:` page against the coverage table, so an unrenamed seed reads as a dozen undeclared pages. Read the names rather than assuming the prefix: gate Step 4's baseline write-back is a sanctioned hand edit, so a committed baseline may also carry operator-named pages. **Two or more affected surfaces:** the copy seeds exactly one of them, and one `.pen` per session is mandatory (`ui-design-resolve.ts` terminates `ambiguous-design` when a second file matches the dialogue key), so there is no copy path for the rest — author their `BASE:` pages in the seeded file by hand and record that in the spec. Empty/missing baseline ⇒ start blank and say so; the editor has to author that file, since `pnpm noldor design pen-bridge` can only open a `.pen` that already exists.
- **Derive the page set from the acceptance criteria before drawing it.** Number the spec's acceptance criteria 1, 2, 3 … and write a `### Design coverage` table under `## Design`, with the columns `Page | Criteria | Shows` (Shows is optional prose for the reader; the check reads only the first two): one row per state the design must show, named `` `FINAL:<surface>: <state>` `` in backticks, with the criteria it shows (`1, 4–6`), plus at most one `not drawn` row for the criteria that have no screen of their own. Every criterion appears on some row, and never on a page row and the `not drawn` row at once; a state that a decision needs rather than a criterion cites `—`. Walking every criterion is the point: a design that draws only the happy path leaves the states its criteria promise undrawn, and the table is where that shows. When the criteria change, change the table and the pages with them.
- **Iterate:** draft 2–3 candidate variants of the main state as pages during the clarify dialogue; converge with the operator; then draw the winner once per row of the coverage table, each a top-level `FINAL:<surface>: <state>` page named exactly as its row. A state drawn as a frame inside another page does not count: the review lanes enumerate top-level `FINAL:` pages only. A surface owns as many `FINAL:` pages as it has rows.
- **Record:** name the chosen variant + considered alternatives in the spec's Design section; link the `.pen` path in the spec; set FD `links.design`.

Any `.pen` this step produced commits WITH the spec at gate Step 2.5 (same commit) — the ratified design on an approved session, the retained-but-unapproved one on a waiver after Seed; a session waived before Seed has none to commit. Once committed the artifact is never edited afterwards; as-built drift lands in the baseline at gate Step 4. Then continue to step 1.6 — the verdict itself waits for step 7.5.
